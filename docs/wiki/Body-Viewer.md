# 模型资源与通用查看器

修炼权限读取必装 Progression 的当前连接投影。未同步或未读时，菜单不显示“修炼”分类的吐纳、经脉入口，直接打开对应窗口也被拒绝；基础“身体 → 检视”仍可打开体表。内部图层、开脉操作使用同一门槛。服务端独立检查请求，客户端隐藏不提供授权。

进度重置会立即关闭吐纳与经脉窗口、清除待发送控制，并撤销内部视图订阅。重新解锁后从权威订阅获取新规则和操作卡；没有客户端独立解锁存档。

## 数据归属

生物附属提供体表、骨架、肌肉、器官与经脉模型及其空间位置。UI 是通用查看框架，不含人体坐标或人体数量分支。当前 Human 提供使用本地玩家基础皮肤的宽臂/窄臂体表、方块骨架、肌肉与器官，以及金色血管式经脉，其他生物可使用完全不同的展示层和几何。

资源格式为经脉框架的 `presentation.proto`，Protobuf `BodyPresentation` schema 1。资源包括精确模板引用、整体包围盒、层、三角网格、可选资源包贴图及逐顶点 UV、静态介绍；节点通过 `BodyTargetKind + target_id` 绑定部位、组织、器官或经脉。多个几何节点可以绑定同一个对象。Blockbench 编辑与装配属于生物内容包，UI 只读取导出资源。

可选 `breathing` 定义吐纳表层、气流入口、动画提供方与动画 ID；节点的 `animation_bone` 绑定随姿态移动的器官。UI 从生物资源读取这些挂点，不维护人体专用坐标；未声明呼吸内容的资源仍可用于只读身体窗口。

节点可用 `minimum_realm` 声明最低展示境界，省略时不限制。检视和经脉窗口都按权威境界筛选可见与可选节点，升降境后重建集合，降境清除已锁定对象的选择。该字段仅控制展示，操作授权由内容附属在服务端独立校验。

模型坐标为局部米，Y 向上，Z 向前；各层共享同一包围盒。几何位置只决定展示与选择，不决定运输距离，不修改身体拓扑。当前资源最多 2 MiB、2048 节点；解码检查版本、有限坐标、包围盒、重复身份、层引用及三角面索引。贴图仅接受资源包内的 PNG 身份，UV 数量与顶点一致且值有限、位于 `[0,1]`；缺少贴图时仍可加载纯色模型。法线亮度和贴图标识在资源加载时缓存，逐帧只做展示变换。

## 宿主入口

`BodyUiModule` 通过 `kizuna_inventory_ui` 入口注册通用“检视”“吐纳”和“经脉”窗口，宿主应取得 Fabric 已加载的同一个模块实例。检视窗口暂时只作只读预览，聚气入口见[独立修炼窗口](Gathering.md)，选脉与操作见[经脉窗口](Meridian-Opening.md)。入口 ID `meridian_ui:body` 保持不变。

1. 在客户端线程调用 `present(BodySnapshot, Identifier)`，传入已认证和校验的身体快照及内容资源 ID。
2. 经 Inventory UI 打开 `meridian_ui:body` 功能入口。
3. 新快照通过 `update(BodySnapshot)` 更新显示。身体 ID 和精确模板版本保持一致，拒绝 revision 倒退。
4. 切换身体或模型前关闭身体、吐纳与经脉及其浮窗，再调用 `present`。断线时模块清除快照与资源引用。

这些是 Java 宿主的已实现入口；跨端数据仍是框架生成消息，不是新 JSON 协议。没有自动读取玩家实体、拉取服务器身体或运行时下载模型的逻辑。安装生物包资源后，也仍需要宿主选择适合当前身体的模型。

## 选择与信息

左侧按生物包层定义生成自绘勾选框，Human 显示体表、骨架、肌肉、器官、经脉。首次只选中 `default_layer_id`，省略时取首层；Human 默认为体表。可随后显示任意组合，也可全部关闭；勾选不重置相机、不改变装配位置。控件不使用 Minecraft 原版按钮，支持鼠标与键盘空格/回车。右侧只显示介绍与数值，不再提供对象列表。

窗口推荐大小为 580×400、紧凑下限为 280×180，单位为 GUI 逻辑像素。首次打开按视口自动收缩，调整分辨率或 GUI 缩放时跟随可用空间；手动调整过的布局由窗口框架保留，可通过外观菜单恢复自动布局。内容区宽度不足 520 时，图层勾选移到顶部并换行；宽窗口使用左侧栏。模型与详情从扣除侧栏和间距后的空间分配，详情独立滚动，较多图层也可滚动。长图层名称裁短显示，悬浮查看完整名称。适配复用原 XML 组件，不重置选择与镜头。

点击实际可见三角面，触发高亮、聚焦和信息更新；叠加时根据真实深度选择最靠前的对象，取消外层勾选可查看内部。拖动累计超过 4 个逻辑像素后转为旋转，释放不误触选择；滚轮缩放，中键复位并清除选择。普通快照刷新保留镜头和选择，结构、境界或显示层变化时重建可见集合；隐藏选中层时清除相应信息，已移除或未解锁的身体对象也不再可选。

选中对象保持高亮，其他对象以 40% 亮度保留空间参照，便于从交织的经脉中追踪整条主干与分支；全身复位恢复原色。该规则对所有生物和展示层通用，不依赖人体经脉 ID。曲线和变粗变细的管壁由内容包提前生成，UI 仍只绘制同一种三角网格。

声明 `player_skin` 的网格使用当前本地玩家的已加载皮肤，按实际宽臂/窄臂选择同拓扑网格与 UV；无玩家时使用资源兜底。选中区域保留皮肤原色，其他区域变暗。臂型改变时才重建相关网格缓冲，绘制和选取共用实际几何。当前 Human 只提供基础皮肤层，未包括帽子、袖套等第二层；黑色吐纳和经脉剪影不套皮肤。

相机复用 Inventory UI 的 `ModelPreviewCamera`；画布使用同一变换矩阵绘制和命中。后侧模型自动转向背面。所有操作只影响当前窗口，不发送身体变更命令。

信息面板读取快照中的部位 HP、组织基础力量/爆发功率/耐力和疲劳、器官 HP/缓存/加工状态，以及经脉容量/储量/吞吐/承受度/损伤/开拓进度。基础组织数值明确标作基础值，没有自行推导攻击伤害或当前有效能力。

快照中已删除的对象会从可见和可选节点中移除。缺少对应状态时显示未同步，不冒充满血。当前没有给新增且未配置几何的组织自动生成模型；内容包需要提供相应资源版本。

## 验证与边界

`BodyPresentationTest` 用非人体“晶囊”验证身份映射、状态显示、删除、模板冲突和贴图/UV 输入边界。游戏内检视由 Human-UI 整合服 smoke 的 `BodyViewerJourney` 在真实玩家身体上验收：五层显示、GPU 实际出图、骨架与肌肉点击、背侧肌肉聚焦转向、全部可见器官与当前境界可见经脉的聚焦、实际 Screen 点击和状态信息，以及多层勾选、全部关闭、隐藏清除选择、眼球叠加、服务端推送刷新保留视角与选择、中键回到全身和关窗清理。原标题画面 demo 已退役；其中“体表剪影与原版玩家模型尺寸一致”的比对在退役前即失败，暂未补回，待 Human 模型修正后恢复。生产 UI 不依赖 Human。

窗口初始层由内容包的 `default_layer_id` 决定，Human 为只显示体表的 `surface`；内部层须右键使用《炁脉札记》后由服务端授权才能勾选，无须看完。当前窗口为只读展示，不发送身体改造或修炼命令。

# 功法配置窗口

通过 Inventory UI 工作台「修炼 → 功法配置」打开。窗口属于工作台，不替换为独立 Screen。
客户端新增必需依赖 `meridian_combat`，服务端模块没有客户端或 owo 依赖。

## 布局与数据

- 左页按当前已学的真实卷册分组，组标题用卷轴物品图标，招式使用各自的技能图标。
  无卷册元数据时稳定平铺，不通过标识字符串猜分类。
- 右页展示选中功法名称、独立简介、投影冷却和当前不可用原因；没有简介时显示「暂无功法简介」。
- 底部十槽固定显示 `1 2 3 4 5 6 7 8 9 0`。两页分别滚动，最小外框为 320×240 GUI 单位。
- 十槽下方不显示操作说明或状态文字，成功配置直接反映在槽位中。
- 十槽下方“姿态设置”调用公开 `MeridianSettings.open(pageId)`，与 Meridian / 设置入口共享
  `meridian_combat:stance` 页及草稿，见[集中设置接入](Central-Settings.md)。
- 图标路径复用 `CombatHud.texture`，书本背景采用 CPA 生成资源，见[背景资源](Combat-Book-Assets.md)。

唯一数据来源为 Combat 客户端 `CombatSlotAccess` 的不可变快照。只有投影变化才刷新模型；
冷却变化不重建左页图标组件。目录移除使旧槽显示失效并保留原配置，不会授予未学功法。

## 交互

点击左页仅选择。将图标拖入十槽会设置或覆盖该槽，拖动载荷只是功法 ID，不是背包物品。
外部松开、Esc、失焦、离开工作台、关闭窗口或断线都取消拖动，不修改原配置。
Esc 取消后必须重新按下鼠标才可开始新拖动。

活动窗口中选中功法后按 `1–9、0` 配置对应槽，长按仅写入一次。文本框、模态控件和其他活动窗口
占用输入时不会触发配置。右键槽位清空。允许同一功法重复配置，不实现槽间交换。

设置、清空和命令共用 Combat 的校验与保存入口，成功立即反映到现有 HUD。
持久化失败通过游戏通知明确显示「仅当前会话生效」，不占用十槽下方区域。
断线释放订阅和交互状态；分档与重载仍由 Combat 原有配置机制负责。

## 验证入口

`./gradlew build` 与 `python3 scripts/check_docs.py` 检查构建、关键状态测试和文档。
安装清单产物准备齐全后，可在 Linux 用以下命令运行独立完整客户端验收：

```bash
xvfb-run -a -s "-screen 0 1280x960x24" ./gradlew :client:runCombatSlotTest
```

存档复制自 Progression 的 GameTest 世界，测试配置独立放在 `client/build/combat-slot-test/`。
报告为 `client/build/combat-slot-results.txt`，实际截图在该运行目录的 `screenshots/`。
长文本与内容撤下边界使用测试端经正式网络通道发送的有界投影，常规截图和学习使用实际千里腿目录。
测试源码不进入发布 JAR。Windows 安装与启动须单独记录，不能用 Linux 验收冒充。

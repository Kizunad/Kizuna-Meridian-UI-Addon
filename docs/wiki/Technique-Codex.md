# 功法谱书页

客户端入口 `CodexClient` 同时将 `TechniqueEffectTooltips.lines` 登记到界面框架的 `StatusNotes`，
让功法组织状态的灰字说明显示在统一状态图标的效果名和时间下面。

功法谱是功法库登记的实物书 `meridian_technique:technique_codex`。右键时功法库在客户端发出
`TechniqueCodex.OPEN`，本附属的客户端入口 `CodexClient` 在这个事件上翻开 `CodexScreen`。
书页是独立 Screen，不进 Inventory UI 工作台：屏幕正中两页羊皮纸，没有窗口外框和顶栏按钮，Esc 合上。
书最大 600×390 GUI 单位，小屏幕上四边各留 8 单位。
书翻开时不画原版 HUD（`CodexScreen` 实现界面框架的 `VanillaHudHidden`）：书没盖住的边上不会露出聊天栏的行首、快捷栏和状态栏，合上以后照常。

谁拿到书、什么时候拿到不归本附属管：第一次学会一卷时由 Threatening 的进度奖励送书，配方见 Progression 进阶树。
书页只读当前玩家自己的已学列表，不改学习或功法配置。

## 两页内容

- 左页是全谱目录：功法库初始化期登记的每一卷按书分组，新功法包装上就出现；每本书和全谱都有完成度。
- 右页是一本书。书有引言（功法包语言文件 `codex.intro.<书>`）就放在最前，各卷按目录顺序往下排。
  - 已学：实色卷轴，写式名、简介，点卷头展开数值与条件。
  - 未得：剪影加问号，式名不露，只写来源暗示和还没学会的前置卷。
  - 够不着（最低一式的境界高于身体当前境界）：剪影角上标境界，写「方可施展」的境界要求、
    功法包的一句威力（`codex.power.<卷>`）、来源暗示和前置。缺句子时显示键名，验收一眼可见。
- 身体境界取自身体投影 `BodyUiModule` 的快照；快照还没到时按凡人算。

正文由 `CodexLines` 按页宽折好：中文按字折并守避头尾（句读、闭括号不落行首，开括号不留行尾），
英文按词折，换行处的空格丢掉。折好的行都不超宽，标签不会再折一次。

## 来源暗示

来源是进服时服务端发来的那份登记（`TechniqueVolumeSourcesClient`）：各附属在服务端登记
「哪类生人修到哪一境会这卷」和「哪个出身的仇家身上带着这卷」。本附属只拼展示句子，不参与掉落判定。

1. 功法包自己写了 `codex.source.<卷>` 就用它。
2. 否则只取同时出现在这卷掉落声明里的生人：会而不掉的不算；每种生人留最低会它的那一境。
3. 四种以上生人用「各路」句式；否则写出生人名，按人人都会还是少数人会、最大掉落声明是否不低于 0.2
   选句式。数字只用来选句式，不出现在文字里。
4. 登记了出身仇家的另起一句；都没有就写下落不明。

句式在本附属语言文件 `codex.hint.*`。中英文均用 `{entities}` 表示生人名、`{realm}` 表示境界、
`{origin}` 表示出身。新版按 `meridian_ui.codex.separator` 连接多个生人名。书引言、威力句和书完成进度
在各功法包，都由 Gemini 按事实文件写成。

## 点亮

读卷学会时右上角弹一张原版进度样式小卡「功法谱 · 新添一卷」，写卷名和这本书的新进度，
同时以 UI 音量轻响一声紫水晶风铃。凑齐一本书不另弹小卡，由功法包里那本书的进度（`book_completed`）来报。
新学的一格记成「新」，下次翻到那本书时剪影在一秒内褪成实色、边框明暗起伏；看过才清掉。
「新」只记在本次游戏里。

## 验证入口

`CodexLinesTest` 覆盖避头尾和英文折行。安装清单产物准备齐全后，在 Linux 运行完整客户端截图：

```bash
xvfb-run -a -s "-screen 0 1280x960x24" ./gradlew :client:runCodexTest
```

客户端测试等服务端认定客户端加载完后切到生存模式读第一卷，等进度奖励把功法谱送进读完卷轴空出的主手、
并听到那一声，截拿书的样子；右键翻开总览、
检查破门斩三卷依次为已学、未得、够不着；再读一卷截小卡；重新右键截点亮与播完之后。
截图在 `client/build/codex-test/screenshots/`，结果写 `client/build/codex-results.txt`。

# 独立吐纳窗口

状态：已实现可重复游玩的手动吸呼、Protobuf 控制、Inventory UI 公共路由桥接及 Fabric 宿主通道接入。Human 的必装 Fabric 宿主提供真实玩家、世界区域和持久化；游戏内验收在整合服真实玩家身体上进行。

## 玩家操作

先读《炁脉札记》打开修炼页，再读聚气残卷解锁吐纳。尚未读聚气卷时菜单隐藏“吐纳”，直接打开也被同一权限规则拒绝；读完后显示入口。服务器独立检查残卷进度。撤权时关闭已有吐纳窗口并隐藏入口；窗口工厂仍校验权限并保留直白提示。

场景按钮上方新增“自动吐纳”复选框。开始前可选模式，运行中切换会提交权威意图。自动交替吸呼、只消耗呼吸耐力而不消耗精力；Human 目前映射为双肺呼吸能力和膈肌耐力，低于80%停止，相同接触采样效率为手动50%。勾选后复选框上方常显绿色说明条：持续消耗呼吸耐力（膈肌）、不耗精力、低于停止线自动停下、同样碰到的灵气只吸收手动的百分比；停止线和效率读取 `BreathingView.automatic_minimum_stamina_ratio` 与 `automatic_capture_efficiency`，UI 不写死数值，悬浮提示使用同一句话。自动运行时顶部条改名“呼吸耐力 ..%（不耗精力）”，只看呼吸耐力，并画出红色停止线与“低于80%自动停”；底部提示改为“自动吸呼中 · 中键旋转 · 滚轮缩放”。手动仍取耐力与精力较低者。开脉等其他活动的精力费用独立保留。

打开工作台的“吐纳”（`meridian_ui:cultivation`）。黑底三维场景占满窗口内容，显示半透明打坐玩家，呼吸器官高亮，随空气量扩张、收缩。中键拖动旋转、滚轮缩放；开始前左键也可拖动。身体、五色灵气与气流使用同一透视相机；粒子拥有三轴位置、不同速度与惯性，停气也会游离。独立帧缓冲隔离模型深度，地面先绘制，场景合成后再绘制文字与教学；关闭窗口释放显存。

点击【开始吐纳】，首次显示悬浮指引，确认后进入练习。手动模式将光标放在灵气附近选择三维方向，按住左键吸气、右键呼气，松开停气。口鼻附近只显示五条短流线，整个空间中的灵气由连续气流场推动：吸气向口鼻汇聚，呼气向外扩散；近处和瞄准方向更强，侧面和背面也响应。气流逐渐转向、衰减，粒子保留惯性，需要预判漂移与三维距离。中键旋转时暂停手动吸呼；自动模式按权威吸呼阶段显示正前方气流。已读指引只作为本地偏好保存。

所有控件叠在玩家和粒子所在的三维场景内部：顶部中央为余力文字与黄色进度条，左下角为肺部空气图，底部中央为吐纳按钮，紧接其下为“中键旋转 · 滚轮缩放”操作提示，右下角为“纳入 .. 真元”。控件在场景之后绘制，各自独立命中，中央空白区域继续用于相机和气息操作；位置随窗口边缘调整。详细状态与失败原因在按钮悬浮提示中显示。肺部像素图是蓝色边框、黑色内部，淡蓝色从肺底向上填入；空气标签显示比例，悬浮显示当前升数与器官能力上限。吸满后继续吸气不会增加空气，需呼气；排空后继续呼气同样停止。

余力显示 `min(呼吸耐力比例, 精力比例)`，悬浮分别显示“维持 .. %”“横膈肌耐力 .. %”“精力 .. %”。任一耗尽结束吐纳；没有捕获到灵气的有效吸呼也会消耗资源。暂停、结束和关窗不补满预算。按钮有低强度黄色荧光，按四秒周期缓慢明暗变化，只影响展示。

窗口推荐大小为 560×450，紧凑下限为 280×180，均为 GUI 逻辑像素。框架按视口自动选取外框；场景宽度小于 420 时，肺图与按钮缩窄，纳入量移到右侧按钮上方，四个控件仍叠在同一黑色场景内。首次指引按实际场景宽度换行，窗口缩放不重建吐纳会话。

恢复由框架读取身体动作占用后进行指数结算，UI 只展示返回的余力。Human 提供动作与半衰期，其 Fabric 宿主将动作目录交给权威处理器；有效吸呼占用呼吸肌和注意组织，停气或容量边界后解除，仍被其他动作使用的组织不恢复。关窗不直接增加资源，重开时可按真实空闲区间恢复。

“纳入 .. 真元”显示当前连接中炼化产物实际抵达经脉的累计值（`stored_qi`），不再使用捕获原料量。悬浮分别显示原始灵气摄入（`absorbed_qi`）、累计入脉、当前内腔、身体总量与最大容量。总量包含内腔、外壁、器官缓冲、加工输入和在途，每笔只计一次；预约不额外增加最大容量。累计入脉不包含出生储量及调试注入，也不随消费回减。未完成加工或仍在途的本批不会提前累计；损耗仍按器官配方结算。

纳入悬浮提示另列呼吸器官的当前缓存与运往经脉的在途量；可恢复的摄入/配送失败同时显示在纳入和按钮提示中。经脉满载与吞吐暂时占用有不同解释，活动中的阻塞不代表呼吸已停止，也不把缓存提前记作入脉。

有效吸气、呼气播放平静的 OGG 录音片段，轻声渐入渐出。松键、教学、中键旋转、肺满、排空或失焦会停止声音；关窗立即释放窗口自己的实例。声音跟随权威吸呼状态，同方向回执不重播，切换方向先停止旧实例，不叠加。音量遵循 Minecraft 的玩家音效设置。素材与许可见[吐纳素材](Breathing-Assets.md)。

手动吐纳在粒子靠近口鼻或运动轨迹穿过入口时接收，同段多颗均可处理。Human 当前每颗代表 1 格环境体积，按当前浓度摄入，20% 即时炼化为无属性真元存入肺缓存，80% 损耗回到同一环境来源；例如浓度 1 元/格时一颗产出约 0.2 元。产物随后经真实运输入脉，下一颗不用等前一颗到达。五色是输入属性，游炁仍取得无属性真元；空气量和真元容量独立。

点击【结束吐纳】或关闭窗口停止主动操作，已经入账的加工与在途由宿主继续完成。自动吐纳无需手动输入心跳，切换桌面焦点后仍由服务器驱动；关窗、断线或耐力低于停止线时结束。身体窗口保持只读，五层模型、选取、聚焦、介绍与数值共用更新后的身体快照；两个窗口可独立打开。

## 可信输入与宿主接入

唯一协议源为经脉框架的 `gathering.proto` 与 `breathing.proto`。客户端反投影鼠标，按附近可见粒子细化深度，只提交 `BreathControl` 的动作、三维目标 `aim_x/aim_y/aim_z` 和递增序号；没有时间、剂量、粒子捕获或产出字段。核心每 250 ms 在活动事件边界判断气流与三维入口距离，输入租约 750 ms，断线或停发输入后暂停。

客户端 tick 续期输入，逐帧只更新模型、空气和粒子的展示。粒子按实际快照接收间隔估计速度，有界外推最多 300 ms，再平滑校正，避免固定 250 ms 插值在提前到达的快照之间反复停顿；重生直接从新位置显示。未练习时只添加少量展示游离偏移。展示预测不参与权威捕获。粒子身份和坐标来自宿主，是摄入机会的展示，颜色按区域实际比例抽样，重生不增加库存。

身体预览和吐纳器官的静态网格只上传 GPU 一次，相机、高亮与肺部伸缩通过矩阵和着色器更新，窗口关闭释放网格与帧缓冲。盘坐玩家每个新呼吸相位只蒙皮一次，同时得到绘制顶点和地面高度；不重复计算两套顶点。粒子、拖尾与短流线批量绘制并保留真实深度，界面仍采用 XML + owo-ui。

宿主向 `BodyUiModule.present` 交付已授权身体与内容资源，通过 `bindGathering(Consumer<GatheringRequest>)` 连接本地宿主，响应在客户端线程交给 `receiveGathering`。网络使用 Inventory UI 两个消息，所属模块均为 `meridian_ui:body`、版本均为 1：

| 消息 ID | 方向 | Protobuf 类型 |
|---|---|---|
| `meridian_ui:gathering_request` | 客户端到服务端 | `kizuna.meridian.v1.GatheringRequest` |
| `meridian_ui:gathering_response` | 服务端到客户端 | `kizuna.meridian.v1.GatheringResponse` |

`GatheringBridge.register` 接入宿主已有公共路由。构造器必须同时提供连接、`GatheringSession` 与 `OpeningSession`，不提供缺宿主只读模式。宿主创建绑定身份和身体的会话，用可信生物 `BreathingProfile` 调用 `enableBreathing`；同一身体只安排一个有效会话。按 `nextBoundaryMillis` 安排 `advance`，断线时关闭。环境续窗必须保留库存与已使用预算；停气跨窗后先结清旧区间，不能消费旧闲置时间。

Minecraft 连接固定通过 `meridian:gathering_request` 发送 `GatheringRequest`，在 `meridian:gathering_response` 接收 `GatheringResponse`。首次身体推送后自动查询，窗口打开即可显示呼吸能力。缺必需 Fabric 通道直接报错，不自动切换公共路由。Human 的 Fabric 适配提供此服务，吐纳与行走、恢复共用玩家状态。`bindGathering` 仍可供其他宿主显式绑定本地请求入口，但不会替代必需的 Fabric 通道。

每次执行仍经过身体归属、真实器官、配方、通路、容量、环境供给、版本和私有策略校验。两项组织消耗与成功摄入一起原子提交；未捕获时两份消耗也一起提交。后续加工和运输是独立步骤，失败保留已完成事实。失败码以中文原因展示。

当前响应带完整授权快照，仅交付操作者，须满足 Inventory UI 的 256 KiB 上限。大身体分片和生产订阅裁剪未实现；服务器可用任何语言实现相同契约。

## 必装打坐动画接线

预览直接调用 Player Animations 的玩家网格、骨架与动画 API，模型变为半透明黑色；肺和口鼻按内容的动画挂点附着。动画模型的 −Z 正面统一转换为内容模型的 +Z，挂点同步变换，初始镜头面对玩家正面。缺模型或 `meditate` 明确报错，不使用静态替代。动画呼吸相位跟随空气量，播放本身不授予资源。

必装动画 JAR 内含双体型模型和 `meditate` 资源。Human 按权威状态统一调度打坐、走路和疾跑，并通过唯一 play/stop/result 协议同步外世界玩家。实际位移先正式结束吐纳，再切换运动动画，转头不结束。`MeditationAvatar` 按当前玩家体型采样同一资源，器官和开脉光迹使用骨矩阵附着；预览播放器不发送服务端动画请求。完整装配无需外置动画资源补丁。

## 开发验收

本仓的标题画面吐纳演示及 `gatheringSmoke` 已于 2026-10-22 退役：吐纳入口由 Progression 服务端授权，标题画面没有服务器无法打开。手动吐纳改由 `Kizuna-Meridian-Human-UI-Addon` 整合服 smoke 的 `ManualBreathingJourney` 在真实玩家身体上验收：检视窗口不含修炼操作；四个控件叠在三维场景内、位置与悬浮明细、中央与按钮命中；经 Screen 中键旋转；真实鼠标对准服务端粒子反复吸呼，吸满被肺容量截断、呼空后停止；吸呼音效播放并在松键、排空和关窗后停止；精力确有消耗且本连接有真实摄入；关窗结束权威会话；身体窗口关闭后吐纳窗口可独立打开并再次开始。截图为 `screenshots/breathing-*.png`。首次开始先显示指引、多分辨率下控件与会话保持由同一 smoke 的 `ResponsiveJourney` 验收，自动吐纳由 `AutomaticBreathingJourney` 验收。

环境与身体守恒、跨环境窗口续窗属于宿主逻辑，由 Human 的 `HumanGatheringTest`（手动吐纳可重复、有界且守恒）、`HumanPlayerBodyTest`（玩家吐纳共享环境与保存恢复）及 Framework 的 `OrganIntakeTest`（续窗不回填）回归覆盖。正式 UI JAR 不包含任何开发宿主、权威核心或验收代码。

# 独立吐纳窗口

状态：已实现可重复游玩的手动吸呼、Protobuf 控制与 Inventory UI 公共路由桥接。开发演示使用真实核心和内存身体，生产玩家绑定、世界区域和持久化仍由宿主提供。

## 玩家操作

打开工作台的“吐纳”（`meridian_ui:cultivation`）。黑底三维场景占满窗口内容，显示半透明打坐玩家，呼吸器官高亮，随空气量扩张、收缩。中键拖动旋转、滚轮缩放；开始前左键也可拖动。身体、五色灵气与气流使用同一透视相机；粒子拥有三轴位置、不同速度与惯性，停气也会游离。独立帧缓冲隔离模型深度，地面先绘制，场景合成后再绘制文字与教学；关闭窗口释放显存。

点击【开始吐纳】，首次显示悬浮指引，确认后进入练习。将光标放在灵气附近选择三维方向，按住左键吸气、右键呼气，松开停气。口鼻附近只显示五条短流线，整个空间中的灵气由连续气流场推动：吸气向口鼻汇聚，呼气向外扩散；近处和瞄准方向更强，侧面和背面也响应。气流逐渐转向、衰减，粒子保留惯性，需要预判漂移与三维距离。中键旋转时暂停吸呼。每次练习都需亲自引导，已读指引只作为本地偏好保存。

所有控件叠在玩家和粒子所在的三维场景内部：顶部中央为余力文字与黄色进度条，左下角为肺部空气图，底部中央为吐纳按钮，紧接其下为“中键旋转 · 滚轮缩放”操作提示，右下角为“纳入 .. 真元”。控件在场景之后绘制，各自独立命中，中央空白区域继续用于相机和气息操作；位置随窗口边缘调整。详细状态与失败原因在按钮悬浮提示中显示。肺部像素图是蓝色边框、黑色内部，淡蓝色从肺底向上填入；空气标签显示比例，悬浮显示当前升数与器官能力上限。吸满后继续吸气不会增加空气，需呼气；排空后继续呼气同样停止。

余力显示 `min(呼吸耐力比例, 精力比例)`，悬浮分别显示“维持 .. %”“横膈肌耐力 .. %”“精力 .. %”。任一耗尽结束吐纳；没有捕获到灵气的有效吸呼也会消耗资源。暂停、结束和关窗不补满预算。按钮有低强度黄色荧光，按四秒周期缓慢明暗变化，只影响展示。

恢复由框架读取身体动作占用后进行指数结算，UI 只展示返回的余力。Human 提供动作与半衰期，演示宿主已将其动作目录交给权威处理器；有效吸呼占用呼吸肌和注意组织，停气或容量边界后解除，仍被其他动作使用的组织不恢复。关窗不直接增加资源，重开时可按真实空闲区间恢复。

“纳入 .. 真元”显示当前会话捕获的原料量，悬浮显示权威快照中的身体总真元量与最大真元量。总量包含经脉内腔、外壁、器官缓冲、加工中的输入和在途货物，各账户只计一次；最大量汇总经脉内腔、外壁与器官容量，在途已预留目的容量，不重复增加最大值。原料纳入量与最终炼化产出不同，损耗仍按器官配方结算。

有效吸气、呼气播放平静的 OGG 录音片段，轻声渐入渐出。松键、教学、中键旋转、肺满、排空或失焦会停止声音；关窗立即释放窗口自己的实例。声音跟随权威吸呼状态，同方向回执不重播，切换方向先停止旧实例，不叠加。音量遵循 Minecraft 的玩家音效设置。素材与许可见[吐纳素材](Breathing-Assets.md)。

摄入后的原料经过真实器官加工、运输和入脉。Human 小批配方为 0.05 元五行游离灵气 → 0.01 元无属性游离态真元；0.04 元进入环境释放账。五色是输入属性，醒灵仍取得无属性真元。空气量与真元容量是两份独立资源。

点击【结束吐纳】或关闭窗口停止主动操作，已经入账的加工与在途由宿主继续完成。身体窗口保持只读，五层模型、选取、聚焦、介绍与数值共用更新后的身体快照；两个窗口可独立打开。

## 可信输入与宿主接入

唯一协议源为经脉框架的 `gathering.proto` 与 `breathing.proto`。客户端反投影鼠标，按附近可见粒子细化深度，只提交 `BreathControl` 的动作、三维目标 `aim_x/aim_y/aim_z` 和递增序号；没有时间、剂量、粒子捕获或产出字段。核心每 250 ms 在活动事件边界判断气流与三维入口距离，输入租约 750 ms，断线或停发输入后暂停。

客户端 tick 续期输入，逐帧只更新模型、空气和粒子的展示。粒子按实际快照接收间隔估计速度，有界外推最多 300 ms，再平滑校正，避免固定 250 ms 插值在提前到达的快照之间反复停顿；重生直接从新位置显示。未练习时只添加少量展示游离偏移。展示预测不参与权威捕获。粒子身份和坐标来自宿主，是摄入机会的展示，颜色按区域实际比例抽样，重生不增加库存。

身体预览和吐纳器官的静态网格只上传 GPU 一次，相机、高亮与肺部伸缩通过矩阵和着色器更新，窗口关闭释放网格与帧缓冲。盘坐玩家每个新呼吸相位只蒙皮一次，同时得到绘制顶点和地面高度；不重复计算两套顶点。粒子、拖尾与短流线批量绘制并保留真实深度，界面仍采用 XML + owo-ui。

宿主向 `BodyUiModule.present` 交付已授权身体与内容资源，通过 `bindGathering(Consumer<GatheringRequest>)` 连接本地宿主，响应在客户端线程交给 `receiveGathering`。网络使用 Inventory UI 两个消息，所属模块均为 `meridian_ui:body`、版本均为 1：

| 消息 ID | 方向 | Protobuf 类型 |
|---|---|---|
| `meridian_ui:gathering_request` | 客户端到服务端 | `kizuna.meridian.v1.GatheringRequest` |
| `meridian_ui:gathering_response` | 服务端到客户端 | `kizuna.meridian.v1.GatheringResponse` |

`GatheringBridge.register` 接入宿主已有公共路由。宿主创建绑定身份和身体的 `GatheringSession`，用可信生物 `BreathingProfile` 调用 `enableBreathing`；同一身体只安排一个有效会话。按 `nextBoundaryMillis` 安排 `advance`，断线时关闭。环境续窗必须保留库存与已使用预算；停气跨窗后先结清旧区间，不能消费旧闲置时间。

每次执行仍经过身体归属、真实器官、配方、通路、容量、环境供给、版本和私有策略校验。两项组织消耗与成功摄入一起原子提交；未捕获时两份消耗也一起提交。后续加工和运输是独立步骤，失败保留已完成事实。失败码以中文原因展示。

当前响应带完整授权快照，仅交付操作者，须满足 Inventory UI 的 256 KiB 上限。大身体分片和生产订阅裁剪未实现；服务器可用任何语言实现相同契约。

## 可选打坐动画

安装 Player Animations 且提供 `meditate` 资源时，预览复用它已加载的玩家网格、骨架与动画，模型变为半透明黑色；肺和口鼻按内容的动画挂点附着。动画模型的 −Z 正面统一转换为内容模型的 +Z，挂点同步变换，初始镜头面对玩家正面。缺少资源时使用生物包静态表层。动画呼吸相位跟随空气量，播放本身不授予资源。

动画项目现有打坐资源及 Protobuf 播放/停止定义，但本地消息处理器和网络接线尚未交付。因此当前复用独立预览播放器，没有通过该协议控制外世界玩家。

## 开发验收

```bash
./gradlew -PhumanAddonDir="../Kizuna-Meridian-Human-Addon" -PplayerAnimationDir="/path/to/animation-checkout" :client:runDemo
xvfb-run -a ./gradlew -PhumanAddonDir="../Kizuna-Meridian-Human-Addon" -PplayerAnimationDir="/path/to/animation-checkout" -PgatheringSmoke=true :client:runDemo
```

普通演示打开只读身体与独立吐纳窗口，使用 Human 可信出生函数、100 元区域库存和真实请求处理器。关闭并重开窗口不会重新初始化；整个演示进程重启才创建新内存身体。

`gatheringSmoke` 经实际 Screen 点击检查控件均在三维场景内、四处定位与输入命中、资源悬浮明细、声音管理器的吸呼播放与停止、教学、反复吸呼、吸满呼空、两项身体消耗、炼化入脉、关窗停止、独立重开和跨环境续窗。身体、区域、环境释放账合计始终为 100.36 元。成功标记为 `client/build/demo/gathering-smoke-ok.txt`，截图为 `screenshots/breathing-*.png`；`uiSmoke` 单独保护原模型交互，并检查实际帧缓冲中的模型像素，防止 CPU 可以选中而 GPU 网格被裁剪。

Human、内存 Store 和验收代码只在 demo 源集，正式 UI JAR 不包含开发宿主或权威核心。
